# План улучшения фингерпринт-стека

> Контекст: после деплоя `1522cae` доля капчи снизилась с **84% → 63%** (срез 6ч).
> Капча всё равно остаётся №1 проблемой (207/326 ошибок). Дальнейший прогресс возможен
> только через улучшение качества фингерпринта/поведения, т.к.:
> - прокси мобильные, IP не банится Яндексом;
> - всего 4 прокси — ротация уже на пределе;
> - `showcaptcha_url` — это детект ПО БРАУЗЕРУ И ПОВЕДЕНИЮ, а не по IP.

---

## P0 — что делать в первую очередь (быстрые победы)

### 1. Аудит UA / Client Hints консистентности
Подавляющее большинство капч ловится на этапе показа `showcaptchaFAST` (PoW) — это значит, что Яндекс отбраковывает браузер ещё до выдачи. Самый частый разрыв: `User-Agent`, `navigator.userAgentData`, `Sec-CH-UA-*` заголовки и `navigator.platform` рассинхронизированы.

**Действия:**
- Прогнать все активные профили через `test_fp_check.py` + сравнить против эталонного Chrome 145 на macOS/Windows (тот же major UA).
- Для каждого профиля проверить:
  - `navigator.userAgent` ≡ `userAgentData.brands` major
  - `navigator.platform` ≡ платформе из UA
  - `Accept-Language` соответствует `navigator.languages[0]`
  - `screen.width/height` ≡ `window.outerWidth/Height` (без 0 в одном из них)
- Помеченные «грязные» профили — поставить в re-warmup или вывести из ротации.

**Проверка:** доля `captcha` за 24ч должна упасть ниже 50%.

### 2. Жёстче ограничить «грязные» профили
Сейчас топ-10 профилей дают 4-7 капч за 6ч (по 1-2 в час). Это значит, что
ни один не «сгорел» катастрофически, но фоном много медленных деградаций.

**Действия:**
- Добавить в `tasks/yandex_search.py` метрику `profile_captcha_rate_24h`.
- Если у профиля ≥ 5 капч/24ч → автоматически отправлять в очередь warmup
  на 1-2 часа (`tasks.yandex_warmup`) и снимать с поисковой ротации на сутки.
- Реализовать через периодический beat-таск, не в hot-pathе.

### 3. Bound the FIRST captcha call (доделка деплоя)
В логах: `Captcha budget [search-results]: +310s/240s` — сам бюджет работает,
но первая капча всё равно занимает 5+ минут. Subsequent calls fast-fail (это и есть выигрыш),
но первый звонок надо bound-ить тоже.

**Решение:** прокинуть `remaining_budget` внутрь `handle_yandex_protection`
и передать его как `timeout` в Capsola API + ограничить общий wall-clock внутренним watchdog (asyncio.wait_for / signal.alarm для sync).

## P1 — структурные улучшения

### 4. Полный переход поискового пути на Camoufox
В репо уже есть `celery_yandex_search_camoufox` (отдельный воркер, см.
`/memories/repo/camoufox_search_backend_2026_04_30.md`). Camoufox имеет встроенные anti-detect патчи
(WebGL noise, Canvas, AudioContext, WebRTC, fonts) — фактически готовый фикс
для большинства fingerprint-сигналов.

**Действия:**
- Сравнить captcha-rate `celery_yandex_search` vs `celery_yandex_search_camoufox`
  за тот же период. Если camoufox даёт <30% капчи — мигрировать всю ротацию.
- Тестовый прогон: 100 задач, оба воркера, одинаковые ключевые слова.
- Если camoufox быстрее в среднем (и реже капчи) — выключить старый stock-playwright путь.

### 5. Канонизировать WebGL/Canvas noise
Сейчас в `app/init_scripts/` (или аналог) есть несколько вариантов JS-патчей.
Нужно убедиться, что:
- WebGL `getParameter` возвращает СТАБИЛЬНЫЕ значения для одного профиля (детерминированный seed по profile_id), а не случайные при каждом запуске — Яндекс склеивает сессии и видит «дрожь».
- Canvas `toDataURL` тоже детерминирован per-profile.
- AudioContext `getChannelData` тоже.

**Метрика:** прогнать `test_consistency.py` дважды на одном профиле — хеши должны совпасть.

### 6. Поведенческий слой (mouse / scroll / dwell)
`showcaptchaFAST` детектит «пустой» браузер — отсутствие микро-движений мыши
до клика. Надо добавить:
- На SERP перед кликом — 3-7 секунд скролла + 1-2 «случайных» движения мыши вне таргетной ссылки.
- На таргетном сайте — dwell 30-90 секунд, 1-2 скролла, 1 клик в нерелевантную область.
- Все паузы — log-normal (μ=2.5, σ=0.4) вместо `random.uniform`.

В `tasks/yandex_search.py` уже есть `human_pause` — нужно проаудитить, что он
вызывается на всех ключевых этапах (между набором запроса и отправкой,
перед кликом, после загрузки SERP).

## P2 — стратегические шаги

### 7. Расширить пул прокси
4 мобильных прокси на 10 воркеров — каждый IP видит ~2.5 параллельных сессии.
Это очень плотно, даже если Яндекс не банит по IP, повторяемые комбинации
(IP + UA + behavioral) повышают подозрительность.

**Рекомендация:** минимум 8-10 мобильных прокси (по 1 на воркер) + ротация
по принципу sticky-per-task (один task = один IP в течение всей жизни).

### 8. Fingerprint-валидатор на старте задачи
Перед каждым `yandex_search_click_task` делать GET на `https://yandex.ru/internet`
или аналог и парсить отчёт. Если IP-based геолокация (от мобильного оператора)
рассинхронизирована с `navigator.language` / `Accept-Language` (например,
прокси выдал немецкий 4G, а профиль `ru-RU`) — пропустить задачу или
поменять профиль.

### 9. Метрики и дашборд
Сейчас captcha-rate измеряется ad-hoc через psql. Нужно:
- Добавить в `prometheus.yml` метрики `captcha_rate_per_profile`,
  `captcha_solve_duration_seconds`, `silhouette_attempts_histogram`,
  `not_found_after_reclassify_count`.
- Настроить Grafana алерт: `captcha_rate_24h > 0.5` → уведомление.

### 10. Отдельный «cold start» warmup для новых профилей
Текущий warmup (`/memories/repo/profile_warmup_system.md`) хорошо разогревает
существующие. Но новые профили из `create_mobile_profiles.py` сразу идут в бой и горят.
Добавить obligatory 4-6h warmup phase (Яндекс главная → новости → погода → карты → видео)
перед первым `yandex_search` таском.

## Приоритетная последовательность работ

1. **Сейчас (день 1):** P0.1 (UA audit) + P0.2 (грязные профили на re-warmup) + P0.3 (bound first captcha) — ожидаемый эффект: captcha-rate 63% → ~40%.
2. **Неделя 1:** P1.4 (Camoufox A/B) + P1.5 (детерминизм noise) — ожидаемый эффект: ~40% → 20-25%.
3. **Неделя 2:** P1.6 (поведенческий слой) + P2.7 (расширить прокси) — ожидаемый эффект: 20-25% → <15%.
4. **Постоянно:** P2.9 (метрики/алерты), P2.10 (cold-start warmup).

## Что НЕ делать
- Не пытаться обходить капчу через смену IP/прокси-ротацию — Яндекс детектит браузер, не IP.
- Не увеличивать таймауты Capsola — silhouette-точность 50% фундаментальна, лучше быстрее провалиться и переразогреть профиль.
- Не добавлять `--disable-blink-features=AutomationControlled` руками — Camoufox/playwright-stealth уже патчит это правильно; ручные правки часто ломают консистентность.
